# 项目提案：拾光集 · 二手交易平台

本文档沿用第 2 周在 README 中确定的项目，记录项目名称、目标用户、核心业务场景和业务模型，并作为第四周单体应用与数据库持久化实现的依据。

## 项目名称

拾光集 · 二手交易平台（SecondLight）

## 目标用户

| 角色 | 简单说明 |
|---|---|
| 买家 | 想买二手物品的学生和居民，需要方便地找到商品、放心下单 |
| 卖家 | 想转让闲置物品的学生和居民，需要方便地发布商品、管理订单 |
| 平台管理员 | 负责审核商品、处理违规和纠纷 |

买家和卖家是同一个用户在不同交易里的身份。前期的开发主要围绕买家和卖家，管理员相关功能放到后面。

## 优先实现的业务场景

**买家下单购买一件在售商品。**

大致过程是：卖家的商品已经上架，买家在商品列表里找到它，点击下单，系统先确认商品还在售，再生成一个订单，订单的初始状态是"待支付"。

选这个场景先做，主要有三个原因：

- 它是整个平台最核心的一环，没有商品被买走，其他功能（议价、评价）都没有意义。
- 它刚好用到下面两个核心模型，范围不大，适合作为起步。
- 后面课程里的库存锁定、服务拆分、事务一致性，都是从"下单"这件事展开的。

议价聊天、互评、商品审核这些功能先不做，等这个场景跑通之后再逐步加。

## 两个核心模型

### 商品（Item）

| 字段 | 说明 |
|---|---|
| id | 商品编号 |
| title | 商品标题 |
| description | 商品描述 |
| price | 价格 |
| category | 分类，比如教材、数码、生活用品 |
| condition | 成色，比如全新、九成新 |
| quantity | 数量，二手商品大多只有一件，默认是 1 |
| status | 状态：待审核、在售、已下架、已售出 |
| sellerId | 卖家编号 |
| createdAt | 发布时间 |

### 订单（Order）

| 字段 | 说明 |
|---|---|
| id | 订单编号 |
| itemId | 对应的商品编号 |
| buyerId | 买家编号 |
| sellerId | 卖家编号 |
| price | 成交价格 |
| status | 状态：待支付、待发货、已发货、已完成、已取消 |
| createdAt | 下单时间 |

### 两个模型的关系

订单通过 `itemId` 关联一件商品，并通过 `buyerId`、`sellerId` 记录交易双方。商品与订单按历史记录看是**一对多**：商品可以因订单取消而再次上架并产生后续订单；但因为商品数量默认是 1，一件商品同一时间最多只能有一个有效订单。下单成功后，商品从"在售"变为"已售出"；订单取消后，商品恢复为"在售"。

用户本周先不单独建模型，订单和商品里先用 `buyerId`、`sellerId` 记录是谁。等后面做认证的时候，再补用户模型。

## 第四周业务建模

### 本周要实现的核心业务流程

本周围绕"买家下单购买一件在售商品"实现一条完整流程：

1. 买家提交商品编号和买家编号，发起下单。
2. 系统读取商品，检查商品状态和买家身份；不符合下单规则时拒绝请求，不创建订单。
3. 校验通过后，按商品当前价格和卖家编号生成"待支付"订单，并将商品状态更新为"已售出"。
4. 后续取消订单时保留订单记录，并将商品状态恢复为"在售"，以便再次出售。

商品与订单的创建、状态更新属于同一次业务操作，持久化实现时应保证两者一致，避免订单已生成而商品仍可被重复购买。

### 参与流程的实体及关系

- **商品（Item）**：提供标题、价格、卖家编号和在售状态，是下单的对象。
- **订单（Order）**：记录买家、商品、下单时的成交价格、订单状态和创建时间。
- **关系**：每个订单只关联一件商品；一件商品可以关联多条历史订单，但同一时间最多只有一个有效订单。订单保存下单时的价格和买卖双方编号，作为交易记录。

### Service 层业务规则

**仅允许买家购买当前处于"在售"状态、且由其他用户发布的商品。** 如果商品不是在售状态，或买家编号与商品的卖家编号相同，Service 必须拒绝下单且不创建订单。该规则可通过对已售商品、非在售商品和卖家自购分别提交下单请求进行验证。

本节的模型和规则已在 `monolith/` 中落地：`Item`、`Order` 为 JPA 实体，`ItemOrderService` 在事务中锁定商品并检查下单规则，`MarketplaceController` 提供商品与订单 REST API。订单创建和取消会在同一数据库事务里更新订单及商品状态。应用使用 MySQL 持久化数据，字段、关系和约束见 [`docs/database.md`](database.md)。

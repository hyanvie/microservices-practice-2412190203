# Week 04：单体应用与数据库持久化

## 本周目标

在第三周创建的 `monolith/` Spring Boot 工程上，逐步实现拾光集二手交易平台的一条核心业务流程。本周第一步是明确业务流程、参与实体及 Service 需要检查的业务规则；后续再实现模型、Service、REST API 和数据库持久化。

## 业务建模

### 实现思路

选择"买家下单购买一件在售商品"作为核心流程，参与流程的两个实体是商品（Item）和订单（Order）。订单保存商品编号、买家编号、卖家编号、下单时价格和订单状态。商品与订单按历史记录为一对多关系，但商品数量默认是 1，因此同一时间最多只能有一个有效订单。

下单时由 Service 检查商品是否处于"在售"状态，以及买家是否为商品卖家。校验通过后创建"待支付"订单并将商品标为"已售出"；校验失败时拒绝下单且不创建订单。订单取消后保留订单记录，并将商品恢复为"在售"。订单创建和商品状态更新应作为一致的业务操作持久化。

业务模型和规则详见 [`docs/project-proposal.md`](../../project-proposal.md) 的"第四周业务建模"部分。本次提交完成的是业务建模文档，尚未声称已经实现后续 Java 业务代码或数据库功能。

### 运行与验证

业务建模本身是文档工作，不需要启动服务。为确认文档更新没有影响第三周已有工程，可在仓库根目录运行：

```bash

```

验证结果：第三周已有测试全部通过（`BUILD SUCCESS`）；该结果只验证现有 Spring Boot 工程，不代表下单业务已经实现。

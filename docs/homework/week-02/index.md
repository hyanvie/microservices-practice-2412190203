# Week 02：项目选题与功能规划

## 项目选题

### 最终选题

**拾光集 · 二手交易平台（SecondLight）**，面向校园及周边社区的二手物品交易系统，本学期全程使用这一个项目。

### 选题说明

**1. 项目名称**：拾光集 · 二手交易平台（SecondLight）。

**2. 要解决的实际问题和业务背景**：校园及周边社区中闲置物品很多，但交易渠道分散（班级群、朋友圈、公告栏），存在信息难检索、议价沟通记录易丢失、陌生人之间缺少信任背书、交易流程缺乏统一状态跟踪等问题。平台通过线上化的"发布、沟通、成交、评价"流程降低沟通和信任成本。

**3. 主要目标用户及其需求**：

| 角色       | 需求                                                   |
| ---------- | ------------------------------------------------------ |
| 买家       | 快速搜索商品、与卖家议价、流程清晰的下单、参考卖家信用 |
| 卖家       | 方便发布和管理商品、及时收到咨询和订单通知、积累信用   |
| 平台管理员 | 审核商品合规性、处理违规、仲裁交易纠纷                 |

**4. 选择该题目的原因**：业务场景真实贴近生活；买家、卖家、管理员诉求差异明显；认证、消息、事务、服务拆分等课程技术点在本项目中都有真实的业务需求，不用生硬凑功能；和课堂选课示例没有直接关系。

**5. 项目的初步边界，以及为什么适合逐步演进**：本学期聚焦发布、搜索、议价沟通、下单与模拟支付、交易互评这一条完整闭环；不对接真实支付网关，不做物流轨迹跟踪，不做推荐算法。项目天然分为用户、商品、订单、聊天、评价五个职责清晰的模块，先做成单体，后续可依次加入数据库持久化、服务拆分、认证、消息、事务、监控和部署，每一步都有对应的业务理由。

### 确定过程

**第一步：列出候选并按标准筛选。** 从作业给出的六个方向中，按下面四条标准逐个评估：

- 是否有明确的业务背景和多个用户角色
- 功能是否足够丰富、能支撑一学期的持续演进
- 后续课程任务（服务拆分、认证、消息、事务、监控、部署）是否有自然的业务需求
- 是否和常见选题、课堂示例有区分度

| 候选题目         | 评估                                                         |
| ---------------- | ------------------------------------------------------------ |
| 宠物医院系统     | 角色丰富，但病历、收费等规则依赖专业领域知识，业务理解成本高 |
| 购物系统         | 模块成熟，但是最常见的选题，区分度较低                       |
| 图书借阅系统     | 业务简单清晰，但消息、事务等场景较弱，演进空间有限           |
| 健身房会员系统   | 预约、签到流程比较单一，事务和消息场景有限                   |
| 餐厅点餐系统     | 出餐流转有特点，但角色偏少，场景相对单一                     |
| **二手交易系统** | 角色多、业务闭环完整，且认证、消息、事务需求都由业务自然产生 |

**第二步：确定选题。** 综合以上评估，选择二手交易系统。它在四条标准上表现最均衡，尤其是"聊天议价对应消息、下单锁库存与支付对应事务、实名与信用对应认证"这几处，业务需求和课程技术点能一一对上，适合在后续课程中逐步演进。

**第三步：划定边界。** 为了保证本学期能完成，将真实支付、物流跟踪、推荐算法列为暂不实现，聚焦主业务闭环。
